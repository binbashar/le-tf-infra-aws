# Version-support scanner

This package scans declared EKS and RDS/Aurora versions, not deployed resource
inventory. Read [the runbook](../../../docs/version-support/README.md) and the
[workflow](../../../.github/workflows/version-support.yml) when changing behavior.

## Dependencies and tests

Run from the repository root:

```bash
PYTHONPATH=@bin/scripts uv run --quiet \
  --with-requirements @bin/scripts/version_support/requirements.txt \
  --with pytest \
  python -m pytest ./@bin/scripts/version_support/tests/ -q
```

The tests use fixtures, mocks, and botocore stubs; no AWS login is required.
Dependency installation can require network access. Keep this environment
separate from Leverage's `.venv`: the scanner requires `python-hcl2` 8.x and
`SerializationOptions`, whereas Leverage can require an incompatible parser.
Do not fix an import failure by upgrading Leverage's environment in place.

For an existing isolated environment with the requirements and pytest installed,
the CI-equivalent command is
`PYTHONPATH=@bin/scripts python -m pytest ./@bin/scripts/version_support/tests/ -q`.

## Behavioral contracts

- `discover.py` does filesystem/HCL parsing without AWS. `lifecycle.py` handles
  catalog lookups and classification. `report.py` renders results;
  `__main__.py` owns modes and exit status. Slack/GitHub posting belongs to the
  workflow, not the Python scanner.
- Preserve both EKS argument names, `cluster_version` and `kubernetes_version`.
  Respect the supported RDS engine allowlist and family-specific major versions;
  do not accidentally scan ElastiCache, OpenSearch, or DMS as RDS.
- Cover literal pins, supported variable/local resolution, and common/account
  tfvars precedence. Unresolved values, parse errors, missing dates, and AWS
  failures must remain visible; they must never imply a clean bill of health.
- Disabled detection checks every path segment with `rstrip().endswith("--")`.
  Both `name --` and `name--` are valid, including disabled parent directories.
  Disabled findings are reported but do not fail the PR gate.
- PR mode blocks active `EXTENDED` and `UNSUPPORTED` findings; warnings and
  unknowns do not block. AWS lookup failures return success with a warning and
  `ran=false`; this is deliberately different from a successful check. Cron mode
  reports findings without failing the gate. Preserve these distinctions in tests.
- Keep AWS pagination and missing/partial response coverage. Use fixed dates and
  stubbed responses in regression tests so they do not depend on today's catalog.
- Fixture `.tf` files under `tests/fixtures/` are test data, never deployable layers.
  Preserve their exclusion from repository discovery and Atlantis autodiscovery
  (`'@bin/scripts/**'` in root `atlantis.yaml`). Discovery with the fixture tree
  itself as the root must still work.
- `docs/version-support/status.md` is generated by `make version-support-table`.
  Do not hand-edit status rows to hide findings or regenerate it with fabricated
  data. A scanner-code edit does not automatically require a live AWS scan.
